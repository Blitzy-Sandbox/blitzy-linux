Key Design Decisions

1. Serialization Format
Chosen: Flattened Device Tree (FDT)
Over: protobuf, custom binary, sysfs

FDT is existing kernel infrastructure; KHO selects LIBFDT in Kconfig. Enables hierarchical metadata with zero new dependencies.

Ref: kernel/liveupdate/Kconfig:12 (select LIBFDT)

2. Subsystem Integration Model
Chosen: Callback Registration
Over: centralized orchestrator

Each subsystem registers its own file handler with preserve/freeze/retrieve/finish callbacks, ensuring subsystem autonomy.

Ref: include/linux/liveupdate.h (struct liveupdate_file_ops)

3. Failure Recovery
Chosen: Session-Scoped Cleanup
Over: full rollback / partial recovery

Partial deserialization failures are intentionally leaked; recovery expectation is a full reboot. Simplifies error paths.

Ref: luo_session.c, luo_file.c (explicit comments on leak-by-design)

4. FD Preservation
Chosen: Token-Based Mapping
Over: direct FD number mapping

Tokens decouple old and new kernel FD number spaces; PRESERVE_FD returns a token, RETRIEVE_FD accepts it.

Ref: include/uapi/linux/liveupdate.h (LIVEUPDATE_SESSION_PRESERVE_FD, LIVEUPDATE_SESSION_RETRIEVE_FD)
